## 1. 원인 분석

### F1 — 탄창이 3개로 되돌아감
- 보급 상자는 탄창을 **더하기만** 한다 (`Gun.AddSupplyMagazines` = 최대 × 비율, 최대치 제한). 줄이는 코드는 없다.
- 실제 원인은 **라운드 정리 규칙**: `Gun.OnRoundCleanup → ResetForPickup` 이 재시작·다음 라운드 모두 탄창·예비 탄창을 **시작값(StartMagazines = 3)** 으로 되돌린다 ("스테이지마다 새 총을 들고 나간다"는 기존 의도).
- 보스 처치 → 다음 라운드에 들어가며 아껴 둔 탄창이 3개로 줄고, 테스터는 이것을 "보급을 받았더니"로 인식했다. (1차에서 넣은 다음 라운드 지급 +2 는 이 리셋 **뒤에** 더해져 5개가 된다)

### F2 — 지형 때문에 획득 불가
1. **경사면 착지**: 상자는 기울지 않고 레이캐스트 지점에 수평으로 놓인다. 경사가 크면 한쪽이 지형에 묻힌다.
2. **조준 레이가 지형에 막힘**: `PlayerInteractor` 는 조준 레이에서 **트리거가 아닌 콜라이더(지형)** 를 먼저 맞으면 거기서 멈춘다. 묻힌 쪽에서 다가가면 프롬프트가 뜨지 않는다.
3. **도달 불가 지형**: 구덩이·절벽 아래·좁은 바위 틈 등. 상호작용 거리(몸 중심 ~ 상자 3m)에 들어갈 수 없다. (2라운드 보스 쫄이 구덩이에 갇힌다는 피드백과 같은 지형)

### F3 — 높은 건물 위
- 1차 수정: 레이캐스트가 처음 맞은 콜라이더가 Ground 레이어가 아니면 버린다 → 지붕 위는 막힌다.
- 남는 경우: Ground 레이어 **지형 자체가 높은 곳**(절벽 위·고원)인데 플레이어 발 높이 + 5m 이하인 경우, 또는 맵 소품 중 Ground 레이어로 된 구조물. 위에서 보기엔 "높은 곳"이지만 올라갈 길이 없다.
- 즉 **"레이어·높이"만으로는 "갈 수 있는 곳"인지 알 수 없다.**

### F4 — 보급 무기 미등장
- 1차 설계 B장(샷건·저격총·로켓·유탄·SMG 1회용)은 **설계만 하고 보류**했다.
- 그 사이 무기 테이블이 바뀜: 산탄총(2005)·저격소총(2006)·기관단총(2004)은 **Loadout(출발 전 선택·해금) 무기**가 됐고, `Category = Supply` 는 **로켓 발사기(2007)·유탄 발사기(2008) 둘뿐**이다.

### F6 — 맵 밖 낙하 위험
- 낙하 후보는 플레이어 기준 20~60m 링에서 뽑는다. 플레이어가 맵 가장자리에 있으면 후보가 맵 밖으로 나간다. 맵 밖에도 Ground 지형이 이어져 있으면 그대로 떨어진다.

## 2. 설계안

### S1. 낙하 지점 = "플레이어가 걸어서 갈 수 있는 곳" (F2·F3·F6) ★핵심

맵(`SciFiMap`)에 이미 **NavMeshSurface**(몬스터 이동용, 지형·건물·나무 레이어 포함)가 있다. 이것으로 도달 가능 여부를 판정한다.

```
후보 XZ (20~60m 링) → 위에서 레이캐스트 (기존)
  ├ 처음 맞은 것이 Ground 레이어?         (기존 — 지붕·바위·나무 위 제외)
  ├ 플레이어 발 높이 + 5m 이하?            (기존)
  ├ [신규] 경사 ≤ 최대 경사(25°)?          hit.normal 과 위쪽의 각도 — 묻힘 방지
  ├ [신규] NavMesh 위?                     NavMesh.SamplePosition(hit.point, 1.0m) — 맵 밖·지붕 섬 제외
  └ [신규] 플레이어에서 길이 이어짐?        NavMesh.CalculatePath(플레이어 → 지점) == PathComplete
                                           — 구덩이·절벽 위·고립된 지붕 NavMesh 제외
```

- 길 찾기는 레이캐스트보다 비싸므로 **앞의 값싼 검사를 모두 통과한 후보만** 계산한다 (투하 1회에 최대 30후보, 25초에 한 번 — 부담 작음).
- 플레이어 위치는 `NavMesh.SamplePosition(player, 2m)` 로 보정. 플레이어 근처에 NavMesh 가 없으면(점프 중·NavMesh 없는 테스트 씬) **길 검사만 생략**하고 나머지 조건으로 투하 (테스트 씬 호환).
- 착지 위치는 NavMesh 보정 지점이 아니라 **레이캐스트 지점** 그대로 (보이는 지면에 정확히).
- 실패 경고의 탈락 사유에 `경사 / NavMesh 밖 / 길 없음` 추가.
- 데이터: 최대 경사·NavMesh 탐색 거리는 **코드 상수** (기획 조정 대상 아님, 기준 문서: 내부 판정 값 = 코드 상수). 기획이 조정하고 싶다면 ConfigTable 행으로 (→ Q4).

### S2. 획득 판정 보강 (F2)

- **상자 콜라이더를 위로 키운다**: 상자 트리거(BoxCollider)를 렌더러보다 위쪽으로 0.5m 정도 늘려, 조준 레이가 지형보다 상자를 먼저 맞히게 한다. (이미 XZ 로는 `pickupPadding` 만큼 넓힘 — 같은 방식)
- 착지 위치를 경사에 맞게 **가장 높은 모서리 기준**으로 살짝 올린다 (S1 의 경사 제한과 함께면 최대 수 cm).
- `PlayerInteractor`(플레이어 담당 코드)는 **수정하지 않는다.**

### S3. 획득 못 한 상자 정리 (안전장치)

- 지금은 필드 상자가 `SupplyMaxActive`(5)개면 **투하가 멈춘다**. 혹시 갈 수 없는 곳에 떨어진 상자가 쌓이면 보급이 영영 끊긴다.
- 착지 후 **일정 시간(기본 90초)** 이 지나면 빛기둥이 깜빡이다 사라진다. 시간은 ConfigTable `SupplyLifetime` (0 = 사라지지 않음).
- 사라질 때 `SupplyCollectedEvent` 는 발행하지 않는다 (획득이 아님). 사운드·HUD 가 알 필요가 있으면 → Q5.

### S4. 라운드가 바뀌어도 아껴 둔 탄창 유지 (F1)

- `Gun.OnRoundCleanup` 규칙 변경:
  - **처음부터 재시작(FullReset)**: 지금처럼 시작값.
  - **다음 라운드**: 탄창 가득 + 예비 탄창 = `max(현재, 시작값)` (부활 때와 같은 규칙 `RestoreAmmoForRevive` 재사용).
- 그 뒤 다음 라운드 지급(+2)이 더해진다 → "아끼면 보상받는" 구조. 최대치(6) 제한은 그대로.
- 보급 무기 칸은 지금처럼 라운드마다 비운다.
- 이 규칙은 **무기 담당(Gun) 코드**의 기존 의도("스테이지마다 새 총")를 바꾸는 것이라 → Q1.

### S5. 다음 라운드 지급량 (F5)

- 피드백: 수류탄이 남지 않으니 라운드 시작 때 **꽉 채워 주면** 최대 보유량 강화가 의미 있어진다.
- `RoundStartSupply` 에 "가득 채움" 옵션: ConfigTable 값이 **-1 이면 최대치까지**, 0 이상이면 그 개수만큼 (현재 2).
- 권장: 수류탄 **-1(가득)**, 회복 팩 2, 예비 탄창 2 → Q2.
  - 수류탄 파우치 강화(최대 +1, +2)를 사면 다음 라운드부터 바로 더 받는다 → 강화 선택 이유가 생김.
- 배너 문구는 실제 증가량 그대로 ("수류탄 +3").

### S6. 보급 무기 (F4) — 범위 결정 필요

1차 설계 B장을 현재 무기 테이블에 맞게 고친 안:

| 안 | 내용 | 작업 범위 |
|---|---|---|
| **(권장) S6-a 2종으로 시작** | `Category = Supply` 인 **로켓 발사기·유탄 발사기**만 보급 무기로. SupplyTable 에 Weapon 행 2개 (`WeaponId` 열), 획득 = `ISupplyWeaponUser.EquipSupplyWeapon`, 탄을 다 쓰면 칸에서 사라짐(B-3) | 보급 + GunSlot. 플레이어 프리팹에 두 총이 이미 있음 (P2) |
| S6-b 5종 (원안) | 샷건·저격총·SMG 도 보급용 **별도 행**(예: 2105 보급 샷건, Category = Supply) 추가 | 무기 담당과 협의: 같은 총 모델의 Gun 오브젝트를 하나 더 두거나, 한 Gun 이 Loadout·Supply 두 행을 쓰도록 구조 변경 |
| S6-c 계속 보류 | 테스터에게 "미구현" 안내만 | 없음 |

- 보급 무기가 들어가면 보급 상자 종류 = 수류탄 팩 / 회복 팩 / 무기 상자. 무기 상자 가중치는 SupplyTable `Weight` 로 조정 (권장 시작값: 수류탄 40 · 회복 40 · 로켓 10 · 유탄 10).
- 무기 상자에도 지금처럼 **예비 탄창 충전**을 같이 줄지 → Q3.

## 7. 추가 설계 — 상황에 따라 바뀌는 보급 확률 (Q-A~Q-D 권장안 확정 · 구현 완료, 플레이 확인 전)

> 요청: ① 수류탄·회복 팩 상자 확률은 플레이어의 현재 보유량에 따라 조정 ② 무기 상자 확률은 웨이브 몬스터 수가 급증할 때, 플레이어가 보급 무기를 다 썼을 때 상승

### 7-1. 방식 — 기본 Weight × 상황 배율

`SupplyTable.Weight` 는 **기본값**으로 두고, 투하 순간 상황 배율을 곱한 값으로 뽑는다 (`SupplyDef.Pick` 에 가중치 함수 인자 추가). 배율 계산은 보급 모듈의 새 클래스 `SupplyDropWeights` 가 담당.

| 상자 | 배율 | 계산 |
|---|---|---|
| 수류탄 팩 | **보유량 배율** | 채움 비율 `f = 현재 / 최대` → `Lerp(NeedMax, NeedMin, f)`. 0개 = ×2.0, 가득 = ×0.25 (0 이 아니라 아주 드물게) |
| 회복 팩 | **보유량 배율** | 같은 방식 (회복 팩 기준) |
| 무기 상자 | **급증 배율 × 소진 배율** (상한 ×4) | 급증 중 ×2.5 · 보급 무기를 다 쓴 뒤 ×2.5 · 둘 다면 ×4(상한) |

### 7-2. 판정 조건

- **몬스터 급증**: `MonsterSpawnedEvent` 를 보급 모듈이 구독해 **최근 10초 소환 수 ≥ 12** 이면 "급증" 시작 → **30초 유지** (투하 간격 25초라 급증 중 최소 1번은 투하됨). 웨이브 테이블 수정 없음
  - 참고: 1라운드 스테이지 2 시작(55초) 부근 `202` 웨이브는 6초에 11마리, `208` 은 4초에 9마리 — 기준 12 는 스테이지 전환·겹치는 웨이브에서 걸리는 수준
- **보급 무기 소진**: GunSlot 이 탄을 다 써서 보급 무기를 버린 순간부터 **다음 무기 상자가 투하될 때까지** 소진 배율 유지
  - 지금 `SupplyWeaponChangedEvent(이전, 0)` 은 소진·라운드 정리 둘 다에서 발행돼 구분이 안 됨 → 이벤트에 `Depleted` 필드 추가 (보완점 G1)

### 7-3. 예시 (기본 40 / 40 / 10 / 10)

| 상황 | 수류탄 | 회복 | 로켓 | 유탄 | 무기 합계 |
|---|---|---|---|---|---|
| 평소 (둘 다 절반 보유, 각 ×1.125) | 41% | 41% | 9% | 9% | 18% |
| 수류탄 0 · 회복 가득 | 73% | 9% | 9% | 9% | 18% |
| 급증 (절반 보유) | 32% | 32% | 18% | 18% | 36% |
| 급증 + 무기 소진 (절반 보유, 상한 ×4) | 26% | 26% | 24% | 24% | 47% |

> 평소 상황에서 무기 합계가 18% 로 지금(20%)보다 낮아진다 (보유량 배율이 절반 보유에서 ×1.125 라서). "조금 낮다" 는 의견을 반영하려면 기본 무기 Weight 를 **10 → 15** 로 올리는 것을 권장: 평소 25% · 급증 46% · 급증+소진 57%

### 8-1. 근접 획득 (조준 → 상자 근처에서 F)

현재: `PlayerInteractor`(플레이어 모듈)가 조준 레이로만 대상을 찾는다 → 3인칭·긴박한 상황에서 상자를 정확히 겨눠야 해 불편.

```
SupplyCrate  ── 획득 영역 SphereCollider(트리거, 반지름 pickupRadius) 추가 · IProximityInteractable(표식 계약) 구현
PlayerInteractor.FindTarget
  1) 조준 레이 대상 (기존 — 여러 상자 중 하나를 골라 집을 수 있게 우선)
  2) 없으면 몸 중심의 OverlapSphere(트리거 포함) → 내가 들어가 있는 획득 영역 중 가장 가까운 IProximityInteractable
  → 기존과 같이 InteractFocusChangedEvent → 프롬프트 HUD, F → TryInteract
```

| 항목 | 방식 | 근거 |
|---|---|---|
| 상자 영역 판정 → 대상 선택 | **직접 처리** (PlayerInteractor 가 물리 쿼리로 찾고 `IInteractable.Interact` 직접 호출) | 상호작용 요청과 성공 여부(반환값)가 다음 처리 조건 → 직접 호출 |
| 근접 허용 여부 | **Core 계약 `IProximityInteractable : IInteractable`** (멤버 없는 표식) | 다른 상호작용 대상(테스트 무기 픽업 등)은 지금처럼 조준만. 기존 `IInteractable` 변경 없음 |
| 영역 등록/해제 방식 | OnTriggerEnter/Exit 등록이 아니라 **매 프레임 OverlapSphere** | 상자가 파괴돼도 남는 참조·해제 누락이 없다. 프레임당 쿼리 1회라 비용 작음 |
| 획득 반지름 `pickupRadius` (**2m 확정**) | **Inspector (SupplyCrate)** | 콜라이더 크기 = 프리팹 설정 (기준 문서 표: 콜라이더 → Inspector). 밸런스 비교 대상 아님 |

- [ ] 유탄 발사기 획득 카드에서 설명이 잘리지 않음 (카드가 늘어남)
- [ ] 30m 안의 착지한 상자를 조준하면 우측 카드 (이름·설명·거리), 30m 밖·벽 너머·낙하 중이면 안 뜸
- [ ] 상자 2m 안에 들어가 F 프롬프트가 뜨면 조준 카드가 사라짐
- [ ] 수류탄·회복 팩·탄창을 받으면 해당 아이콘이 튀고 "+N" 이 떠오름 (상자 획득·다음 라운드 지급 모두)

### 9-7. 카드 다듬기

- **무기 이름이 안 보이던 문제**: 이름 칸(32pt)이 높이 40px 로 글꼴 줄 높이(약 46px)보다 낮았고, TMP 말줄임 모드는 칸에 안 들어가는 줄을 통째로 숨긴다 → 모든 줄 높이를 `GetPreferredValues` 로 재서 쌓고, 한 줄 칸은 넘침 허용. 이름은 굵게 (설명 바로 위)
- **반투명**: 스킨 배경 스프라이트를 칠하면 흰색 불투명이 되므로 배경 알파를 따로 적용. `cardAlpha = 0.65` (Inspector)

### 9-8. 사격 중 조준 카드 숨김

- 기존 전역 `WeaponFiredEvent`(플레이어가 든 총이 쏠 때만 발행) 구독 → 마지막 사격 후 `hideAfterFire = 0.6`초(Inspector) 동안 조준 카드 표시 안 함, 떠 있던 카드는 바로 숨김
- 보급 무기 획득 카드는 영향 없음 (획득 직후 정보라 사격 중에도 표시)
