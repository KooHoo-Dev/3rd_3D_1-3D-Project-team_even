# 라운드 진행 연결 (BL-032, BL-033)

## 씬 구성

- 진행 오브젝트에 `RunDirector`를 추가한다. `RoundSequencer`와 `RoundBossEncounter`가 함께 추가된다.
- `RoundSequencer.Monster Wave Director`에 씬의 `MonsterWaveDirector`를 연결한다. 해당 디렉터의 `MonsterPool`도 연결한다.
- 보급을 사용하면 `RoundSequencer.Supply Dropper`를 연결한다. 보급 시작 시각(SupplyStartTime)과 투하 간격(SupplyInterval)은 RoundTable 값만 사용한다 (Inspector 타임라인은 제거됨).
- `RoundBossEncounter.Spawn Point`를 보스가 생성될 위치에 연결한다. 비어 있으면 진행 오브젝트 위치를 사용한다.
- 보스 프리팹은 현재 Clypeosaurus Resources 프리팹을 기본으로 사용하며, `Boss Id`는 새 BossTable의 1이다. 프리팹을 직접 연결해도 된다.
- 플레이어는 `IPlayerTarget`을 등록하는 실제 PlayerController를 사용한다. 지상 몬스터·보스가 움직일 수 있도록 NavMesh를 준비한다.
- `KillRewardCollector`, `UpgradeManager`, `UpgradeScreen`을 배치한다. Collector가 재화 지급과 FullReset 시 재화·강화 초기화를 담당한다.
- 기존 RoundTester는 연결된 시퀀서에 RunDirector를 추가하는 테스트 진입점으로 유지한다. 별도로 진행 이벤트를 발행하는 KillRewardTester·WaveDirectorLab 등은 통합 플레이 중에는 끈다.

## 시작과 반복

`Start On Play`가 켜져 있으면 플레이어·풀의 Start가 완료된 다음 프레임에 시작한다. 꺼 두면 버튼 또는 ContextMenu의 `StartRun()`으로 시작한다.

RunDirector의 CurrentRound는 진행 횟수(1, 2, 3…)다. 데이터 조회와 MonsterWaveDirector.StartRound는 계속 1라운드를 사용한다. 강화와 남은 재화를 유지하고, 라운드 획득액과 생성 일정은 매번 초기화한다.

웨이브 시작·보스 전환 시 중단은 RoundSequencer만 직접 호출한다. RoundStartedEvent와 GameStateChangedEvent는 알림이며 웨이브 실행 명령이 아니다. RoundCleanupEvent 구독은 웨이브 중단 안전망으로 유지한다.

## 보스와 보상

보스 시각에 MonsterWaveDirector.StopRound와 보급 자동 투하 중단을 호출한 뒤 BossIntro를 알린다. 플레이어의 3인칭 전환 완료를 받은 다음 보스를 한 번 생성한다. RoundBossEncounter가 플레이어와 BossDef를 ClypeosaurusController.Initialize에 전달하면 해당 컨트롤러가 보스·공격들을 초기화하고 EntranceAttack을 시작한다. 프리팹의 playerSource는 비워 두어도 되며, Start에서 중복 초기화하지 않는다.

BossIntro는 등장 공격의 낙하·포효·회복이 끝날 때까지 유지되고, 이후 BossBattle로 넘어간다. 일반 몬스터는 착지(EntranceAttack.Impacted) 때 MonsterWipeRequestedEvent를 보상 없이 한 번 발행해 정리한다. 등장 공격이 없는 보스는 생성 즉시 정리 이벤트를 발행하고 보스전으로 넘어간다. Spawn Point는 보스 NavMeshAgent가 사용할 수 있는 NavMesh 위에 놓아야 하며, Clypeosaurus 프리팹의 EntranceAttack에는 그림자·충격파 프리팹을 연결한다.

에디터 또는 Development Build에서는 군중전 중 F12를 누르면 보스 등장 시각을 기다리지 않고 BossIntro로 진입한다. Game 뷰에 포커스를 둔 상태에서 사용한다. 웨이브·보급 중단, 카메라 전환, 등장 공격은 정상 라운드와 같은 경로로 실행하며, 보스 등장 이후나 보상·게임오버 중에는 추가 소환하지 않는다. 별도 컴포넌트 연결은 필요 없다.

RoundBossEncounter는 보스의 로컬 Died를 BossDefeatedEvent와 시퀀서의 완료 신호에 연결한다. 기존 보스 이벤트의 MonsterDef는 데이터 이전 중이라 null일 수 있다. 현재 보상은 기존 RoundTable.BossReward를 사용하며, 새 BossTable에 없는 추가 보상 값을 임의로 넣지 않는다.

보상 단계에서는 시뮬레이션을 멈추고 입력·피격을 차단하며 커서를 해제한다. UpgradeManager.Finish가 완료 이벤트를 내면 프레임 끝에서 정리 후 다음 회차를 시작한다.

## 최종 사망과 재시작

PlayerDiedEvent는 부활 가능한 사망이므로 RunDirector가 종료하지 않는다. PlayerFinalDeathEvent가 오면 시퀀스를 즉시 중단하고 프레임 끝에서 GameOver로 전환한다. 같은 프레임에 보상 완료가 와도 최종 사망을 우선한다.

게임 오버 화면(GameOverPanel, GameFlowUiBootstrap 이 자동 생성)의 [재시작]은 RunDirector.RestartRun 을 부른다. RoundCleanupEvent(false)로 전투 중 오브젝트·예약 동작을 정리한 뒤, 실패한 라운드의 시작 체크포인트를 복원하고 같은 라운드를 즉시 시작한다. 재시도는 무기 선택 화면을 다시 열지 않는다. [메인 메뉴]는 SceneTransition 으로 메인 메뉴 씬을 불러온다.

체크포인트는 보상·무기 선택과 RoundStartedEvent의 초기화가 끝나고 RoundSequencer가 첫 몬스터를 생성하기 직전에 RunDirector 메모리에 저장한다. 라운드 번호·재화·레벨별 강화 구매 등급·무기 해금·선택 슬롯과 탄약·수류탄/회복 팩·현재/최대 목숨·시작 위치/시선 방향을 복원한다. 체력과 스태미나는 복원된 강화가 적용된 최대치로 채우고, 사망·이동 속도·반동·장전·부활 보호·임시 공격 효과는 새 시도에 남기지 않는다. 실패한 시도에서 얻은 재화와 소모한 아이템은 라운드 진입 시점으로 돌아간다.

다음 라운드를 시작하면 체크포인트를 새 시작 상태로 교체한다. 파일이나 PlayerPrefs에는 저장하지 않으며 RunDirector 비활성화·씬 종료·게임 종료 시 체크포인트는 사라진다. ReturnToReady를 직접 호출하면 복원 후 Ready에서 기다리고, 이후 StartRun도 저장된 라운드부터 시작한다. 체크포인트가 아직 없는 경우에는 기존의 전체 초기화로 처리한다.

다음 회차(스테이지 클리어 후)는 강화 선택을 마치면 무기 선택 화면이 열리고, RunDirector 는 [출발]까지 Reward 상태로 기다린다(IRoundStartGate). 그 뒤 RoundCleanupEvent(false)라서 강화·재화·수류탄 수는 유지하지만, 총은 모두 시작 탄약으로 돌아가고 보급 무기는 사라진다(스테이지마다 새 출발). 두 정리 경로 모두 예약 스폰·보급·보스·투사체·수류탄·장전·점사·투척 예약을 취소한다. RunDirector를 끌 때는 자신이 멈춘 시뮬레이션 속도를 복구한다.

## 검증

PlayMode 테스트 필터: `HybridShooter.Round.Tests`와 `HybridShooter.Monster.Behaviour.Tests.TestMonsterWaveDirector`.

진행 테스트는 실제 RunDirector·시퀀서·보스·보상 코드를 실행하며, 몬스터 프리팹 예열을 피하기 위해 빈 스테이지와 공격 없는 테스트 보스를 사용한다. 실제 웨이브 생성은 기존 MonsterWaveDirector 테스트에서 확인한다.
